**Truth you can verify** - PKM Assistant 2.2.0

The plugin is now called **PKM Assistant** (`pkm-assistant`) everywhere, it stopped promising
things it did not do, and it lost a third of its weight.

Highlights:

- **External MCP servers on the real protocol.** The old sandbox that ran custom JavaScript
  from your vault is gone; in its place is a proper MCP client (stdio and HTTP). In Settings:
  a preview of the server's tool list **before** you save the configuration, an on/off switch
  per server, presets for five popular servers (filesystem, github, memory, fetch, blender)
  and an import of existing server definitions from Claude Desktop. A new server needs
  explicit consent before its first tool call, and the consent dialog shows the full call
  arguments.
- **Fail-closed security.** File paths are compared in one canonical form at every stage of a
  permission check (no more slipping past forbidden zones with `./`, double encoding or
  letter case); a disabled tool is really blocked, not merely hidden; content from notes,
  memory and tool results is marked in the prompt as **data, not instructions**; text
  generated by the agent does not get the privileges of a human message; background work uses
  the state of the agent that ordered it, not of the one on screen; delegation inherits the
  intersection of parent and child permissions. 13 XSS holes and vulnerabilities in
  dependencies were fixed.
- **Agent permissions finally work.** Four switches in the profile (reading and editing
  notes, creating and deleting files) were saved but never checked. The *Full* preset no
  longer paradoxically narrows an agent to a folder whitelist, and an agent in "assigned
  folders only" mode got web search, page fetching, mail and delegation back.
- **Agent mail v3: simple post.** One message is one file in the mailbox, three actions (send
  / list / read), per-profile invisibility, cleanup of read messages one by one or in bulk, a
  spam limit (20 messages per 10 minutes between a pair of agents) and a bounce counter that
  breaks reply loops. Project Hub (projects, threads, briefs and 12 tools) was removed; it
  never got used.
- **Sub-agents finish the job, and you can see them do it.** Delegation starts in the
  background (the chat no longer freezes), a new *Sub-agent runs* panel in the sidebar shows
  running and finished jobs with expandable steps and a Stop button, you can send a running
  sub-agent an extra message, and the limits (iterations, run time, result length) were raised
  so long research is not cut in half. A model error inside a sub-agent gives a red frame, not
  a false "done".
- **Conversations stopped hanging.** A silence watchdog catches a dead model stream, Stop
  really interrupts a turn (including during a tool call and after the panel is closed), and
  opening a new session no longer kills a conversation in another tab.
- **Agent memory loses nothing.** The active session survives closing the tab, autosave
  appends the tail instead of cutting history down to a summary, sections you added to
  `brain.md` by hand stay put, and the migrator from format v2 to v3 counts every section and
  every paragraph. Fragments cut when a conversation is compacted land in a holding area
  instead of disappearing.
- **Lighter and faster.** The bundle went from **3.0 MB to 2.16 MB** and start-up from **about
  8 seconds to a fraction of a second** (first by cutting two hard-coded delays inherited from
  the earlier code base, then by polishing start-up down to about 52 ms under production
  conditions). Mention suggestions after `@`, the artifact list, memory search and session
  saving are all faster too.
- **Dry-cleaning.** The whole source moved to TypeScript in strict mode, ESLint enforces
  module boundaries, ComfyUI was removed entirely, and dead settings and inert fields are gone
  from the interface.
- **The core layer was rebuilt from scratch.** HTTP and streaming transport (fetch with
  SSE/NDJSON, no more XMLHttpRequest), the plugin runtime (start-up, hardened settings,
  notices, status bar), nine chat model providers and four embedding providers were written
  from the ground up against written-down behaviours and tests.

## Upgrade notes

The plugin identifier changed. **Settings, API keys and data migrate automatically** the first
time the new version starts - nothing has to be retyped by hand. Settings now live in
`.pkm-assistant/settings.json` inside your vault.

Settings keys inherited from the earlier code base are rewritten to the plugin's own
(`pkmAssistant.chat.*`, `pkmAssistant.embedding.*`, `pkmAssistant.notices.*`): platform,
models, hosts, API keys and the embedding model all carry over at start-up, and a backup copy
of the previous settings file is written before the first save in the new shape. Dead keys
from years back are deleted.

Two things are left for you:

1. **Hotkeys have to be assigned again.** Obsidian stores them as `<plugin-id>:<command-id>`,
   and both halves changed.
2. **Delete the old plugin folder by hand**, once you have confirmed the new version works.
   The plugin does not remove it. Until then the plugin list may show two "PKM Assistant"
   entries (the old, inactive one and the new one) - this is harmless.

After the removal of Project Hub, the old agent mail files (projects, threads, briefs and the
old `inbox_<agent>.md` mailbox format) stay in your vault unused. The plugin neither sees nor
deletes them; remove them yourself if you want to.

## Known limitations

- **Desktop only.** The plugin is marked desktop-only and will not start on a phone. Semantic
  indexing in particular is desktop-first.
- **API keys sit in plain text in `.pkm-assistant/settings.json`**, that is, inside your vault,
  until you turn on the secure store (AES-GCM encryption with a master password). The file is
  added to the vault's `.gitignore` automatically, but synchronisation services (Obsidian Sync,
  Dropbox, Google Drive) replicate it along with the vault.
