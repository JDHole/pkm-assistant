**Truth and safety** - PKM Assistant 2.1.0

No new features outside the core. Instead, the plugin stops pretending: what it promises, it
actually does.

Highlights:

- **Semantic search really works.** A meaning-based index of the vault (Orama) is built at
  start-up, follows changes as they happen, and is kept on disk, so a restart does not
  recompute it. Status and a *Re-index* button live in Settings. Desktop-first; on a phone you
  get an honest message. Agent memories and No-Go zones are hard excluded from the index.
- **Fail-closed security.** An agent with a missing or broken tool whitelist gets the minimal
  set of tools, not all of them; a sub-agent cannot run a tool outside the intersection of
  permissions by any route; `web_read` only fetches addresses of known origin (a search result
  or a link you gave it); `.pkm-assistant/` is out of reach of the vault tools; parallel memory
  writes no longer overwrite one another (one queue per file); an XSS hole in the model
  settings was fixed; you get a warning when API keys are stored unencrypted.
- **Limits with teeth.** All agent limits sit in one place and are editable in Settings ->
  Limits. The tool loop has a real hard stop (the last round runs without tools, so the model
  has to answer in text), and tool results are trimmed before they can blow up the context.
- **The plugin slimmed down from 8.35 MB to 3.0 MB.** Token counters show real usage reported
  by the API, and estimates are honestly marked as approximate and calibrate themselves.
- **Agent mail put to sleep behind a kill switch** for the duration of the rework (data
  untouched, bringing it back is a single flag).
- **A big sweep:** dead code removed (the Cohere provider, old tools, legacy formats), ESLint
  enforcing module boundaries, and documentation reviewed so it tells the truth about the state
  of the code.
- **Diagnostics:** a plugin log written to a file, plus a self-test command with a health
  report.
